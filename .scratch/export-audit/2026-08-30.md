The strict Tier 1 list is intentionally conservative: inferred callback, JSX, and option shapes are not named imports. Tier 2 promotes those shapes when scoped examples/tests actually exercise the public path. History shows the remaining true orphans were deliberately added with protocol/renderer features; none is recommended for source deletion in this audit.

| Export | Tier 1 | Tier 2 | Verdict | Recommended action |
| --- | --- | --- | --- | --- |
| `AnimationCompleteEvent` | ORPHAN | ORPHAN | `future-surface` | Keep only as a forward-compatible protocol type for now; document or remove in a future intentional API decision because no public root callback currently consumes it. |
| `PointerAction` | ORPHAN | ORPHAN | `dead` | Do not remove in this documentation-only audit. Revisit in a future API cleanup: `PointerEvent` carries literal pointer types and does not expose this alias. |
| `TransportTerminationDetails` | ORPHAN | ORPHAN | `future-surface` | Keep as the typed diagnostic-details seam used by `TransportTerminatedError`; add a consumer constructor/adapter example if downstream custom transports need it. |

Every other Tier 1 `ORPHAN` is Tier 2 `USED-IN-ANGER`: constituent style vocabulary, component props, event callback types, native integration option types, surface configuration, transport adapters, and the `NamedStyles`/`ExitFunction` seams are exercised structurally. They are not dead code.

## Documentation correction

`docs/getting-started.md` previously said a disabled `Pressable` “reports disabled accessibility state.” The implementation distinguishes interaction `disabled` from the separately retained `accessibilityDisabled` field, while pinned GPUI does not expose a public AccessKit disabled-state builder. The row now states that `disabled` removes interaction and that `accessibilityDisabled` remains wire-retained but is not currently mapped through a public native builder. No source or test files were changed.

## Scope and limitations

This is a usage audit at one revision. A Tier 1 orphan is not necessarily a true orphan: Tier 2 captures constituent types consumed through inferred structural typing. The three exports orphaned in both tiers remain intentionally retained pending a future API decision. No code was removed and no build/test command was run, per the audit constraints.

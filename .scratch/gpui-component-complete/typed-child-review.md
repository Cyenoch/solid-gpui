# NativeItems<T> Host Node boundary review

The inspected typed-child path preserves concrete native types and declared events but **bypasses each child Host Node's full namespace and onLayout**. Direct `styled_element` styles still apply; ordinary `element` styles supplied by an outer wrapper are lost. Generic pointer/key events are not a typed-child-specific regression: NativeComponentProps does not promise them, and ordinary Extensions also return before the generic View/Pressable listeners.

## Where the two paths diverge

Ordinary child: `ChildIterator::next → render_node_for_extension → render_node → extensions::render → instance.render → ElementInstance::build → style → scope_native_element` with native_style=true, or `wrapper Div + style + measure` otherwise. Evidence: [iteration and typed branch](/Users/jgbingzi/workspace/sp/solid-gpui/crates/solid-gpui/src/renderer/extensions.rs:360), [ordinary Extension finalization](/Users/jgbingzi/workspace/sp/solid-gpui/crates/solid-gpui/src/renderer/extensions.rs:567).

## A minimal structural fix

Retain concrete T together with its Host Node provenance and finalization, installing the boundary **during final IntoElement conversion, after the native parent finishes reading and modifying T**. Do not erase T into AnyElement or wrap it in a layout Div before passing it to the native parent.

Let root `crate::native` own `NativeChild<T>`, with a generic `ComponentChild<T>` in vendor that does not depend on solid-gpui. Both retain T and an optional cloneable immutable `Rc<dyn Fn(AnyElement) -> AnyElement>` finalizer, called once for each actual rendering occurrence. A shared single-use closure is insufficient because Sidebar clones sources and renders visible items repeatedly. Support raw-T conversion, read-only `as_ref`, and provenance-preserving `map_native<T -> U>`; IntoElement converts T and then applies the finalizer. This is a generic composition boundary, not a new renderer field on every leaf control.

`NativeItems<T>` carries children with provenance instead of bare Vec<T>. Provenance includes stable node identity, layout subscription/event-route lifetime, and style-placement policy. `next_native` creates it; `build_native` constructs only T. Ordinary and typed rendering share one finalization boundary that executes once. Avoid a public `into_inner` shortcut that silently discards provenance.

Other concrete child containers use the same generic composition boundary. Parents consuming descriptors and generating elements later must carry finalization through to that eventual render, without discarding provenance while extracting fields.

Reuse MeasuredElement's transparent boundary: return the same child LayoutId and delegate prepaint/paint directly. This preserves direct flex/grid items and adds no layout layer. Apply styles directly to Styled T and retain native parent precedence for size/variant. For non-Styled types, preserve ordinary rendering's outer-box style policy without pretending an additional layout box is transparent. Where a parent requires direct layout items, the contract must require native style support or provide explicit parent-specific style adaptation; silently dropping style is invalid.

Finalization installs only the existing node-scope/onLayout/style contract, not every high-frequency event. Lifecycle tokens must prevent deferred callbacks after unmount/epoch replacement from reaching a later node. Construction remains O(n) in consumed children per frame, with no whole-tree scan, global retained provenance table, or double construction per frame. Do not schedule layout callbacks without an onLayout subscriber.

## Key verification scenarios

1. **One mechanism test for scope, layout, and styles:** Two typed children of the same type deliberately reuse local keyed IDs while having distinct node IDs, onLayout listeners, and direct styles. Clicking changes only the corresponding state; a width patch changes only its frame, with equal ordinary/typed style results. A non-Styled child explicitly verifies outer-box styling.
2. **Real ButtonGroup/TabBar parents:** Check group selection, joined borders/variant, Tab indicator bounds, and child onLayout. Reordering preserves Host Node identity. Child onPress remains reachable without a group callback; with a group callback, upstream replacement semantics apply. TabBar explicitly documents that group on_click overrides child on_click, so firing both is not a fix. [Upstream contract](/Users/jgbingzi/workspace/sp/solid-gpui/vendor/gpui-kit/crates/component/src/tab/tab_bar.rs:165)
3. **Nested native Table:** Table→Header/Body→Row→Head/Cell has distinct valid bounds at every level. Parent size/with_ix propagation, col_span, native table accessibility, and narrow/wide resizing remain intact. Transparent scope adds no real layout wrapper.
4. **Lifetime and atomicity:** Keep wrong-concrete-type rejection and no-remount tests. Add rejection of late measurements/events after unmount or epoch replacement, and verify both ordinary and typed children build/finalize once.

Existing children_tests establishes update rendering, slot content, atomic wrong-child-type rejection, and owner retirement only. All listener_id values are 0; no styles, interaction, namespaces, or layout are checked, so these gaps remain possible. [Existing tests](/Users/jgbingzi/workspace/sp/solid-gpui/crates/solid-gpui/src/native/children_tests.rs:56)

These are source findings and proposed tests, not executed results. Real focus/keyboard handling, Tab animation, and narrow/wide Table resizing still require native-window checks. Deterministic tests establish structure and interaction semantics only.

## Default features, conversion coherence, and adapter placement

`crate::native` is available by default, while `gpui-component` and `gpui-base` are optional. `NativeChild<T>`, Clone with T: Clone, map_native, and core IntoElement/Styled implementations depend only on gpui and the root renderer. Do not import `gpui-base` into the default native path. Gate vendor conversions and Sizable/ChildElement/Collapsible/SidebarItem adapters with `#[cfg(feature = "gpui-component")]`. [Feature boundary](/Users/jgbingzi/workspace/sp/solid-gpui/crates/solid-gpui/Cargo.toml:29)

`impl<T> From<NativeChild<T>> for gpui_component::ComponentChild<T>` is **legal**: NativeChild<T> is local and the preceding foreign ComponentChild<T> covers T, leaving no uncovered T before the first local type. It can coexist with vendor's `impl<T> From<T> for ComponentChild<T>`. Two real temporary crates compiled and passed conversion assertions with `rustc 1.98.1 (48a229cea 2026-09-01)`; temporary files were removed. This establishes coherence only, not project compilation or UI acceptance. [Rust orphan/coherence rules](https://doc.rust-lang.org/reference/items/implementations.html#trait-implementation-coherence)

Transfer all fields across the bridge without creating double finalization through NativeChild<ComponentChild<T>>. Vendor may expose `ComponentChild::from_parts(value, finalizer)`, while root decomposition remains crate-private and public consumption preserves the boundary. Styled exposes T's style; Sizable/ChildElement/Collapsible change T through map_native; IntoElement installs scope last. SidebarItem must defer render as described below. Vendor ComponentChild also implements its parents' required traits; optional root forwarding supports Table/generic Sidebar paths that do not convert to the vendor wrapper.

## T→U mapping, repeated Sidebar rendering, and descriptors

`map_native<U>(self, f: impl FnOnce(T) -> U) -> NativeChild<U>` safely preserves provenance if it moves only the value and retains provenance/style policy unchanged, without rendering, finalizing, or regenerating Host Node IDs. Concrete child validation occurs before/during host construction of T; an internal parent conversion to U does not change the registered contract. Mapping must retain one final render root per Host Node. Expanding T into several independent elements or discarding its render body after extracting fields cannot automatically preserve node semantics. ComponentChild also supports T→U; require T: IntoElement only on IntoElement, not on the type or map, so it can carry descriptors such as DescriptionItem.

SidebarEntry→SidebarMenuItem is an explicit one-to-one mapping, preserving native styles in entry.0. TablePart can retain its enum intact through trait forwarding. If a variant must be mapped, transfer complete wrapper provenance and preserve the same root; a bare match result must not replace NativeChild.

**Sidebar Clone is an actual runtime requirement.** `SidebarItem: Collapsible + Clone`, and Sidebar's list callback uses `self.content.get(ix).cloned()`, rebuilding the same item as viewports and redraws change. Non-cloneable Box<dyn FnOnce> is insufficient; Rc<RefCell<Option<FnOnce>>> loses the boundary after its first use. Use Rc<dyn Fn> with immutable host identity/epoch and weak lifetime references, constructing a fresh MeasuredElement per render occurrence. Renderer routing still rejects retired epochs. [Trait](/Users/jgbingzi/workspace/sp/solid-gpui/vendor/gpui-kit/crates/component/src/sidebar/mod.rs:211), [visible-item cloning](/Users/jgbingzi/workspace/sp/solid-gpui/vendor/gpui-kit/crates/component/src/sidebar/mod.rs:449)

**SidebarItem must not render before entering scope.** Its render calls window.use_keyed_state directly. Rendering T before wrapping the resulting AnyElement creates state in the parent namespace. Return `finish(DeferredSidebarItem { value, id }.into_any_element())`, where a private generic RenderOnce invokes `T::render(value, id, window, cx)`. Native render then runs inside the child boundary's request_layout, preserving the native ID argument, collapsed behavior, and concrete T. Do not capture short-lived window/cx borrows when creating the adapter. [State creation](/Users/jgbingzi/workspace/sp/solid-gpui/vendor/gpui-kit/crates/component/src/sidebar/menu.rs:265)

DescriptionPart→DescriptionItem can also transfer provenance, but that alone does not fix style placement. DescriptionItem describes a direct flex item created by its parent. Moving a non-Styled outer Div into this path may leave span/flex_basis on an inner element and change layout. Apply Host style to the parent's existing item-root Div through an explicit styled-finalize/deferred-style hook, then install only transparent scope; alternatively, explicitly restrict unsupported styles in the contract. Retaining a finalizer alone cannot establish descriptor-style correctness. This belongs to the generic render-boundary style policy without adding HostStyle to every leaf control.

Add one essential Sidebar scenario: toggle submenus, scroll items out and back, and reorder two entries sharing local keyed IDs. Open state and onLayout must remain with their Host Nodes; every render occurrence has a boundary and retired epochs receive no late callbacks. This covers real Clone and deferred-render consumption paths.

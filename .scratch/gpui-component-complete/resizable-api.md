Move the generic ComponentChild implementation into gpui-base. ResizablePanelGroup should retain the wrapper and finalize it after injecting native state, axis, and index. ResizableState must align sizes by stable panel keys; dragging must identify the actual panels on both sides of a divider instead of retaining array indices. Validate Panel placement before candidate-tree publication to prevent isolated native Panels from panicking.

## Minimal native state design

### 1. Explicit panel identity

Require a `key: ElementId` on ResizablePanel, with a constructor such as `resizable_panel(key)`. The solid-gpui adapter uses `cx.id()`, the stable Host Node ID. Native Rust callers supply semantic keys rather than enumeration indices or values regenerated during each render. [Host ID](/Users/jgbingzi/workspace/sp/solid-gpui/crates/solid-gpui/src/native/component.rs:85)

The existing `From<T: Into<AnyElement>> for ResizablePanel` and `From<ResizablePanelGroup> for ResizablePanel` create unnamed Panels and conflict with required keys. Remove these implicit conversions and require `resizable_panel(key).child(content_or_group)`. Retain no keyless positional branch, and require no extra JavaScript key property: Host Node IDs suffice. [Implicit conversions](/Users/jgbingzi/workspace/sp/solid-gpui/vendor/gpui-kit/crates/base/src/resizable/panel.rs:120)

Constructor migration is limited to existing resizable tests/examples, base/text/text_view.rs, base/dock/dock_area.rs, component/setting/settings.rs, component/tests/base_compat.rs, and the base resizable showcase. Add keys to those native callers without expanding adapter scope.

### 2. Align complete state by key

Store the key in ResizablePanelState while retaining the ordered public `sizes()` view. Replace count-only synchronization with `sync_panels(axis, specs)`, where specs contain each actual Panel's key/initial_size/size_range/visible. Reconcile old `(panel_state, measured_size)` pairs into the new key order: preserve size and preference for existing keys, initialize new keys from their own policy, and discard removed keys. Reordering only sizes would leave size, bounds, range, and other panel state inconsistent.

A temporary HashMap provides O(n) reconciliation; the unchanged-order render path need not allocate a complete map every frame. Update necessary constraints without structural changes and preserve initial_size's creation-only semantics so props do not overwrite dragged sizes every frame. Track initialization explicitly, for example with a measured flag, instead of treating equality with PANEL_MIN_SIZE as proof of a new panel, as update_panel_size currently does. [Existing initialization](/Users/jgbingzi/workspace/sp/solid-gpui/vendor/gpui-kit/crates/base/src/resizable/mod.rs:200)

Preserving size means size follows identity: a pure reorder in the same container neither exchanges nor reinitializes widths. After insertion/removal, native container rules may redistribute remaining space; this is not a guarantee of permanently fixed pixel sizes. Retain proportional resizing, initial flex policy, range clamping, and settling frames instead of adding another allocation algorithm. [Container allocation](/Users/jgbingzi/workspace/sp/solid-gpui/vendor/gpui-kit/crates/base/src/resizable/mod.rs:350), [settling frame](/Users/jgbingzi/workspace/sp/solid-gpui/vendor/gpui-kit/crates/base/src/resizable/panel.rs:175)

Keys must be unique within a group. JavaScript Host Node IDs already provide uniqueness. Native APIs should reject duplicate keys as contract errors before reconciliation mutates any state. If public insert_panel remains, it must accept a key and enforce the same uniqueness instead of creating anonymous slots.

### 3. Track the actual divider during dragging

Replace persistent resizing_panel_ix with `ResizeDrag { before_key, after_key, axis }`, optionally with a session/generation. It identifies the handle between neighboring panels; resolve temporary indices only for one execution of the native resize algorithm.

- If unrelated panels move, enter, or leave while both keys remain adjacent with valid axis/visibility, continue the drag using freshly resolved indices.
- Cancel if either side is removed or hidden, adjacency changes, or the axis changes. Do not let a retained index resize a new neighbor.
- Group MouseMove/MouseUp callbacks capture state, not paint-time current_ix. Read the live drag when handling each event. MouseMove calls existing resize_panel_at_handle only with valid adjacency and measured bounds. MouseUp completes a still-valid session once and emits one on_resize; cancellation does not fabricate completion.
- on_drag captures both keys and verifies they still identify that group's handle. Panel prepaint updates also carry keys, and structural generations if needed, resolve current identity, and reject retired updates. Old closures must not write to new items by index.
- Clear, reset, and removal consistently retire invalid drags. The worker exits explicitly with fewer than two panels or no successor, removing empty-array subtraction.

Derive Panel and handle GPUI element IDs from panel/adjacency keys as well, rather than retaining panel_ix as UI identity. Keys represent identity only; Panel/State still owns axis, ranges, bounds, and native style precedence.

### 4. Dock requires migration to the same API

Changing Group while leaving Dock's separate count/index synchronization would retain duplicate state logic. Dock already has `PaneNode::id()`; pass it when render_node creates Panels. Merge `sync_split_panels` and its following sync_panels_count into the shared keyed synchronization entrypoint. Preserve adoption of tree sizes only when explicitly changed, plus scale_sizes_to, so each frame does not overwrite dragging or viewport-resize results. [Call site](/Users/jgbingzi/workspace/sp/solid-gpui/vendor/gpui-kit/crates/base/src/dock/dock_area.rs:1029), [Panel construction](/Users/jgbingzi/workspace/sp/solid-gpui/vendor/gpui-kit/crates/base/src/dock/dock_area.rs:1451)

This is a necessary native-state API migration, not a change to Dock's pane tree, persistence format, or drag-and-drop behavior. CachedSplit.sizes still determines whether the tree authorized new sizes. Child ordering belongs in ResizableState instead of two reconciliation algorithms.

## Reject isolated Panels before publication

With `visible=true`, ResizablePanel::render expects state and a panel index. A Panel without a parent Group panics while drawing. `visible=false` returns an empty Div first but does not make the structure valid: showing it triggers the same path. [Native precondition](/Users/jgbingzi/workspace/sp/solid-gpui/vendor/gpui-kit/crates/base/src/resizable/panel.rs:301)

Existing validation checks concrete types from parent to child; a Panel inside an ordinary View has no reverse restriction. [Current validation](/Users/jgbingzi/workspace/sp/solid-gpui/crates/solid-gpui/src/native/component.rs:503) Add a small explicit contract:

1. Add `requires_typed_parent: bool` to ComponentDefinition and enable it only for ResizablePanel. A builder could be `with_typed_parent_required()`; a macro option such as `#[component(typed_parent = true)]` would extend the existing parser and feed Definition. The flag does not prohibit ordinary content inside a Panel.
2. Expose accepted child_type and requires_typed_parent through ExtensionAdapter, reusing element_type. Panel needs a concrete element_type and its actual parent entrypoint must declare consumption of that type. Do not special-case component names or make all leaf components typed-only.
3. Validate the reverse relationship against the same candidate store in SolidRoot::validate_extension_tree. The only legal entries are a direct Extension parent with default_child_group=None, or the generated View belonging to that Extension's **declared default_child_group**. Cross only this declared slot-container layer, never arbitrary View/ScrollView wrappers or ancestors. The selected adapter.child_type must equal Panel.element_type. [Matching content rules for child summaries](/Users/jgbingzi/workspace/sp/solid-gpui/crates/solid-gpui/src/renderer/extensions.rs:25)
4. Root placement, ordinary Views, named slots, and non-consuming parents return InvalidChildren with node/parent IDs. Do not mount the Panel, catch its panic, insert a Group automatically, or degrade it to a Div. Nested layouts explicitly use Group→Panel→Group→Panel; implicit From conversions must not turn a direct Group child into a Panel.
5. Snapshot and Patch already call validate_extension_tree after `candidate.apply_*` and before `self.store=candidate` or native reconciliation, so this validation rejects atomically. Moving a valid Panel into an ordinary container goes through the same check and preserves the old tree, revision, and instances on failure. [Snapshot gate](/Users/jgbingzi/workspace/sp/solid-gpui/crates/solid-gpui/src/renderer.rs:529), [Patch gate](/Users/jgbingzi/workspace/sp/solid-gpui/crates/solid-gpui/src/renderer.rs:609)

The parent restriction belongs to the module contract. Serialize stable requiresTypedParent metadata or derived parentComponents names in ModuleDefinition::description and include it in the digest; never serialize Rust TypeId. If metadata is only for catalogs/docs, remove it from runtime TypeScript descriptors like childComponents. If JavaScript needs it, extend NativeComponentDescriptor too. Regenerate artifacts through the project generator. [Description/digest](/Users/jgbingzi/workspace/sp/solid-gpui/crates/solid-gpui/src/native/module.rs:178), [descriptor stripping](/Users/jgbingzi/workspace/sp/solid-gpui/crates/solid-gpui/src/native/module.rs:253)

## Minimum meaningful verification

- **Layered compilation:** base alone can use a bounded PanelGroup; component compiles SidebarItem/Sizable; root compiles with default and gpui-component features, without a base→component dependency or duplicate alias impls.
- **One key state test:** Give A/B/C distinct measured sizes and verify sizes follow keys through reorder. Middle removal and insertion must preserve existing identities, initial_size, and container-allocation semantics. A drag continues when an unrelated preceding item moves and cancels after either side is removed or the group clears; later mousemove must not panic. Check real state, not a temporary key array.
- **One native drag/layout test:** Preserve two-panel dragging and one on_resize event. Add reorder/removal during dragging, axis changes, and Panel-owned onLayout/style. Verify that the transparent boundary preserves direct flex items and handle hit testing.
- **Publication atomicity:** Reject isolated visible/hidden Panels, Panels in ordinary Views, and Panels in named slots; accept a valid Group child. An invalidating Move must not publish a revision or mount/remount. One slot-aware typed fixture must permit only the default content lane, catching accidental ancestor-search acceptance.

Existing resizable tests cover fixed/flexible initial sizes, external-state settling, programmatic resizing, native dragging, and cross-axis size. They do not establish keyed reordering or removal during active dragging. [Existing tests](/Users/jgbingzi/workspace/sp/solid-gpui/vendor/gpui-kit/crates/base/src/resizable/mod.rs:407) This report specifies checks to retain or add; it does not claim they passed.

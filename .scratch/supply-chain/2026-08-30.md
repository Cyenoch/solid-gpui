The initial dev finding was:

- Advisory: [GHSA-4x5r-pxfx-6jf8](https://github.com/advisories/GHSA-4x5r-pxfx-6jf8), [CVE-2026-49356](https://nvd.nist.gov/vuln/detail/CVE-2026-49356)
- Severity: Low, CVSS 3.2 (`AV:L/AC:H/PR:N/UI:N/S:C/C:L/I:N/A:N`)
- Affected: `@babel/core <=7.29.0`; fixed in `7.29.6` (or Babel 8.0.0-rc.6)
- Impact: malicious source compiled by Babel can cause a source map to be read from the machine when the attacker controls input, can read output, and knows the target source-map path. Trusted-only compilation is not impacted.
- Exposure: this package uses Babel in its Fast Refresh source transformation path (`packages/react-gpui-dev/src/transform.ts`). The source is developer-supplied/local development input, not a network-facing renderer runtime, but the package's transformation API makes the advisory relevant when an application compiles untrusted source.
- Action: compatible patch bump applied to `@babel/core 7.29.6`; no workaround or breaking major was needed.

## CI tooling gap

The workflows currently run build, format, typecheck, test, and embedded checks, but no workflow invokes `bun audit`, `cargo-audit`, or `cargo-deny`. `ci.yml` runs `make ci`; `embedded-bun.yml` runs `make embedded-bun`; release and cross-platform workflows similarly contain no advisory scan. A future CI hardening change can add native `bun audit` for both package directories and `cargo deny check advisories` (with an explicit policy for unmaintained crates), but this audit does not broaden scope by changing workflow behavior.

## Public interface and implementation

`@solid-gpui/vite/compiler` exports:

```ts
interface CompileResult { readonly code: string; readonly map: string }
compile(source: string, filename: string): CompileResult
```

One synchronous operation accepts an authored `.jsx` or `.tsx` filename, emits
universal ES-module JavaScript targeting `@solid-gpui/core/runtime`, and returns
a JSON source map. TSX uses the existing TypeScript erasure pass and composes its
map with JSX lowering. Explicit type imports and declare fields erase; runtime
imports and JavaScript class fields survive. Solid 2 auto-imports stay disabled;
the application's stable Solid 1.9 graph and existing ref ABI remain authoritative.
Unsupported filenames and invalid source throw. The compiler performs no project
resolution, bundling, typecheck, native export, runtime selection or host startup.

`src/transform.ts` was moved to `src/compiler.ts` and renamed to this public
interface; no wrapper or duplicate transform remains. Vite imports it directly,
as do website virtual-preview snippets. Package exports carry source, declarations
and ESM targets. The existing manifest-driven build discovers the entry without
a custom build pipeline. Vite's peer is optional for compiler-only installs; the
plugin still requires Vite when consumed. No CLI/project/artifact/packager code
was changed. The source-map regression moved from the HMR file to the compiler
public seam rather than being duplicated.

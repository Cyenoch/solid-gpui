## Mechanical cut sequence after approval

1. Update the release-prep heading guard to accept the dated heading, if the
   dated Keep a Changelog form is retained. Move the current Unreleased content
   under `## [0.2.0] - YYYY-MM-DD` and leave an empty `## [Unreleased]` section.
2. Run `make release-prep VERSION=0.2.0`; review all manifest and lockfile diffs.
3. Run `make ci` and `make embedded-bun`.
4. Run `make host-release-check`, then `make host-release-bundle`; inspect the
   archive allowlist, checksums, target, version output, and unsigned status.
5. Run both package dry-runs (`bun pm pack --dry-run` in each package) and the
   package consumer smoke already covered by `make ci`.
6. Review the dated changelog, generated locks, archive name, and `git diff
   --check`; commit the version cut and release notes.
7. After the human approves the final commit, create the `v0.2.0` tag and push
   only through the separately approved release procedure. Publish npm packages
   only after registry/token/access decisions are confirmed.

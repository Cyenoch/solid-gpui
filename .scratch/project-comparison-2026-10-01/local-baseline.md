# Local Solid GPUI baseline

Research date: 2026-10-01. Source revision: `e9bc4389c5394e5de1fecb6758d2d06e48877fdb` of `Cyenoch/solid-gpui`; the working tree was clean before research. This is a source assessment, not a cross-project performance benchmark. The lockfile resolves vendored `gpui-pre 0.3.7`, GPUI Kit component/base `0.7.0`, and `rquickjs 0.12.2`; the JavaScript workspace pins Solid `1.9.15` and the universal compiler `2.0.0-rc.9`. Older incident/skill references to GPUI `0.3.3` must not be treated as the current linked version. [Lockfile](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/Cargo.lock#L2407-L2409), [JavaScript pins](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/package.json#L29-L41).

## Implemented strengths

1. **Solid remains the owner of composition and reactive state.** The host configuration implements the universal renderer's mutation operations. It associates mutations with a Solid owner, journals host changes, and schedules one microtask publication. Root transactions and commands share an ordering boundary. [Host configuration](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/packages/solid-gpui/src/renderer/host-config.ts#L9-L105), [universal operations](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/packages/solid-gpui/src/renderer/host-config.ts#L132-L218).
2. **Updates are transactional rather than a series of publicly visible partial edits.** `HostTree` finalizes dirty properties, builds an initial Snapshot or subsequent Patch, and publishes the revision only after transport admission. Failed publication rolls back the private host graph. Rust's patch transaction separately retains an undo journal until validation succeeds. [JS publication](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/packages/solid-gpui/src/renderer/host-tree.ts#L108-L225), [Rust transaction](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/tree/transaction.rs#L34-L164).
3. **Native ownership is explicit.** Core input keeps text, selection, composition, edit sequence, caret scrolling, and undo history in Rust. A controlled echo is admitted only when it acknowledges the native edit sequence and no composition is active. Retained custom views have explicit mount/update methods rather than JS access to GPUI handles. [Input state](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/renderer/input.rs#L46-L81), [controlled synchronization](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/renderer/input.rs#L654-L668), [NativeView](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/native/component.rs#L234-L245).
4. **Transport pressure and foreground scheduling have bounds.** The shared surface router limits queued input and output by count and bytes, exposes termination to all routes, and retains frame order. The native commit pump bounds one foreground turn by message/byte budgets so a continuously ready producer yields. These are resilience and scheduling properties, not proof of a specific latency. [Surface router](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/packages/solid-gpui/src/renderer/surface-router.ts#L75-L174), [commit pump](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/host/commit_pump.rs#L13-L117).
5. **Native contracts have a canonical source and runtime checks.** The v6 Bebop schema, generated bindings, strict structural guard, semantic validation, and exact Extension catalog identity make mismatched hosts fail explicitly. The empty registry rejects unsupported extensions before publication. This is materially more than TypeScript declarations over an unchecked native ABI, although it is not an application sandbox. [Protocol](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/docs/protocol.md#L1-L97), [registry and adapter boundary](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/renderer/extensions.rs#L142-L194).
6. **Development recovery preserves the tool, not an invalid stream.** `DevSession` revokes an old session before native replacement, refreshes Cargo inputs, and keeps Vite watching after failure. Bindings cannot enter the old session through HMR. [Supervisor](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/packages/solid-gpui-vite/src/dev-session.ts#L27-L172).
7. **Verification distinguishes correctness from display performance.** The repository has rollback, reorder, callback-generation, and transport-pressure tests, plus a real native profiling path. Its performance guide explicitly separates CPU attribution, presentation cadence, physical input latency, and monitor overhead. [Renderer regressions](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/packages/solid-gpui/tests/renderer.test.ts#L1065-L1257), [measurement definitions](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/docs/performance-analysis.md#L9-L48).
8. **Delivery exists beyond documentation.** GitHub's first-party latest-release response reports a non-draft, non-prerelease `v0.5.2`, published 2026-09-29, with Gallery archives and checksum sidecars for macOS ARM64, Windows x86-64, and Linux x86-64. The research did not download or launch them. npm's first-party latest endpoints also report `0.5.2` for core, Vite, router, and Shiki. This proves release availability, not clean-machine or physical-desktop acceptance. [Release](https://github.com/Cyenoch/solid-gpui/releases/tag/v0.5.2), [release metadata](https://api.github.com/repos/Cyenoch/solid-gpui/releases/latest), [Vite registry](https://registry.npmjs.org/@solid-gpui/vite/latest), [router registry](https://registry.npmjs.org/@solid-gpui/router/latest), [Shiki registry](https://registry.npmjs.org/@solid-gpui/shiki/latest).

## Concrete weaknesses and boundaries

### TestHost uses the wrong default selection unit

The public helper's `dispatch` input path defaults `selectionStart` to `utf8ByteLength(event.text)`, whereas TextInput's native/public selection contract uses UTF-16 offsets. A local probe through `TestHost`, a controlled TextInput, signal echo, and the actual encoded Patch reproduced `新值` → selection 6 rather than 2, and `🙂` → selection 4 rather than 2; both carried `ackEditSeq = 1`. This defect is in the testing helper, not evidence that real native input emits UTF-8 selections. [Helper default](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/packages/solid-gpui/src/testing.ts#L127-L146), [native selection synchronization](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/renderer/input.rs#L654-L667), [controlled prop acknowledgement](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/packages/solid-gpui/src/renderer/props.ts#L95-L121).

The first probe correctly reproduced the CJK case, then incorrectly assumed an implicit surface ID of 1 could be reused in the same process and stopped at the second case. The corrected probe used distinct surface IDs 101 and 102 and completed both cases. All roots were unmounted in `finally`; no native process was started. Recommended fix: use UTF-16 offsets and add one meaningful Unicode test asserting selection/acknowledgement, not merely the text value. No fix was made during this research.

Reproduction shape: run a script with `bun --conditions=browser` that imports `createRoot`/`TextInput` from `packages/solid-gpui/src/index.ts`, `TestHost` from `src/testing.ts`, and `createSignal` from `src/runtime.ts`. For each string, create a fresh TestHost and root with a distinct surface ID, mount a controlled TextInput whose `onChangeText` sets its value signal, dispatch `{ type: "input", text }` against the committed input node, await one microtask, and decode the final submitted Patch with the actual generated Envelope. Inspect the text-input property's `selectionStart`, `selectionEnd`, and `ackEditSeq`. The observed output was:

```json
{"text":"新值","expectedUtf16Offset":2,"actualSelectionStart":6,"actualSelectionEnd":6,"ackEditSeq":1}
{"text":"🙂","expectedUtf16Offset":2,"actualSelectionStart":4,"actualSelectionEnd":4,"ackEditSeq":1}
```

### Release rehearsal still hardcodes protocol v5 after the v6 cutover

The current canonical Rust constant is `PROTOCOL_VERSION = 6`; the host's startup and version strings interpolate that constant. However `scripts/host-release.sh` checks an exact `protocol=v5` version string, and both process and embedded candidate smoke scripts still expect v5 diagnostics/version output. `host-candidate-smoke` invokes the release check before its smoke script. A correctly rebuilt current v6 host therefore cannot satisfy those stale string assertions. This is a source-proven verification-path mismatch; the full release build/rehearsal was not executed here. It does not imply the separate published QuickJS gallery packages are broken. [Canonical version](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/protocol.rs#L1-L16), [host output](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/host/mod.rs#L1575-L1583), [release assertion](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/scripts/host-release.sh#L169-L174), [process smoke assertions](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/scripts/host-candidate-smoke.sh#L90-L105), [embedded smoke assertions](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/scripts/host-embedded-candidate-smoke.sh#L190-L206), [task composition](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/scripts/tasks.ts#L589-L594).

Recommended response: consume canonical release/protocol metadata in these checks instead of duplicating version literals, then run the affected rehearsal. One meaningful cutover/rehearsal check is more useful than accumulating tests that only import modules.

### Incremental commits are not incremental native render regions

`apply_decoded_message` uses the Patch change set to reconcile relevant state, but accepted commits notify `SolidRoot`. Its Render method enters the tree root; ordinary View children recursively construct GPUI elements. Extensions and VirtualList have their own paths, so this must not be generalized to every native component or to offscreen list rows. This is specifically an element-construction/invalidation observation: it does not imply that every native state object is recreated, that GPUI ignores internal caches, or that every pixel is repainted on screen. [Commit notification](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/renderer.rs#L638-L738), [root render](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/renderer.rs#L1268-L1293), [primitive recursion](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/renderer/paint/mod.rs#L285-L347).

The previous [native incremental commit investigation](../native-incremental-commit/report.md#baseline-and-cpu-attribution) found a large commit improvement while forced CPU draw remained dominant for its 20,000-node, unvirtualized fixture. That historical result is not a benchmark of the current revision or of any alternative. Its cached-pane experiment was rejected because rendered content stayed stale. A proper render-region design needs commit, native-only input, scrolling, async content, animation, inherited styles, and geometry invalidation; adding `.cached()` mechanically is incorrect. Cached interaction handlers also need an explicit contract: current primitive handlers capture surface/epoch/revision/listener metadata during element construction, and JS resolves callbacks against event revision. An optimization cannot silently retain obsolete event metadata or retarget old events to new callbacks. [Authoritative cache requirements](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/docs/performance-analysis.md#L304-L321), [native handler metadata](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/renderer/paint/mod.rs#L361-L384), [callback lookup](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/packages/solid-gpui/src/renderer/dispatch.ts#L29-L39).

The actually linked vendored GPUI supports `Entity::cached(style)`, but it lays out from a definite outer style instead of measuring its contents. Cache reuse checks bounds, content mask, inherited text style, dirty views, and refreshing state. Therefore a general region design cannot assume intrinsically sized content has the same cache semantics as a fixed pane. [Current cached-view contract](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/vendor/gpui/src/view.rs#L233-L244), [current cache key checks](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/vendor/gpui/src/view.rs#L478-L523).

### External-consumer setup exposes SDK implementation constraints

Consumers must align npm versions with a matching SDK source checkout, use an unpublished Rust crate, and reproduce the SDK's workspace-root Cargo patch/profile requirements. npm installation supplies no native executable. The small example lives inside this workspace and therefore does not itself prove a frictionless standalone installation. `doctor` diagnoses constraints but does not remove them. There is a packed-consumer smoke test: it exercises installed SDK exports, compilation, routing, and worker behavior outside the workspace, but its Rust host only prints a test catalog and does not link GPUI or open a desktop window. Thus the recommendation is to extend existing verification, not to claim consumer tests are absent. [Consumer prerequisites](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/docs/getting-started.md#L14-L59), [Cargo patches](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/Cargo.toml#L64-L72), [example prerequisites](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/examples/desktop-app/README.md#L22-L58), [packed test host](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/scripts/package-pack-smoke.ts#L415-L456).

Recommended response: one standalone scaffold with exact SDK/native revisions and correctly owned workspace patches; a prebuilt default host for applications that do not declare native modules; source builds remain explicit for custom Rust integrations. Prebuilt-host availability is a proposal, not an existing feature.

### Product surface exceeds the qualified delivery surface

The shared renderer supports external Bun, embedded Bun, QuickJS, and an experimental WASM host. Embedded Bun's packaging and toolchain are substantial, while its distribution guide states that no target is claimed as supported or verified and that repository CI does not yet qualify its static package. The shipped/verified repository package is the QuickJS website, not a general packager for arbitrary applications. This is a prioritization risk, not proof that runtime plurality is architecturally wrong. [Runtime matrix](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/docs/runtimes.md#L1-L20), [delivery boundaries](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/docs/distribution.md#L1-L40), [embedded qualification](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/docs/distribution.md#L223-L230).

Recommended response: prioritize a clearly qualified first-app and application-packaging path; retain separate experimental tiers rather than suggesting all runtime/target combinations have equal maturity.

### Catalog identity conflates interface and implementation source

`ModuleDefinition::description()` includes module source and component source; `refresh_digest()` hashes that entire description. Several built-in component definitions use `with_contract(include_str!(...))` with full implementation files. Consequently a source-only change, including line endings or a comment in an included file, changes the catalog digest even if the exported props/events/commands do not change. The distribution and CI guides explicitly require LF because source bytes participate in contract identities. [Digest construction](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/native/module.rs#L228-L254), [included implementation source](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/crates/solid-gpui/src/components/resizable.rs#L255-L263), [checkout consequence](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/docs/ci.md#L121-L125).

This selected-source lock can intentionally reject a different implementation even when its types match, so it is not an unsafe-runtime defect; it is also not a complete hash of the executable and its transitive dependencies. The criticism is that a value called a catalog/contract digest carries an additional build-source responsibility and leaks that responsibility into checkout and binding churn. Consider separate canonical contract identity (including explicit semantic versions for non-type behavioral contracts) and exact SDK/build identity. Keep both checks explicit and fail closed; do not introduce permissive compatibility or let old source run unnoticed.

The root README says GitHub Pages is awaiting first deployment. On the research date the public URL returned the website shell, and browser capture showed the rendered landing page. npm's first-party registry reports `@solid-gpui/core@0.5.2` as latest. The guide's conditional wording about publication is not itself a false statement; the specific first-deployment notice is. [Stale notice](https://github.com/Cyenoch/solid-gpui/blob/e9bc4389c5394e5de1fecb6758d2d06e48877fdb/README.md#L21-L26), [public website](https://cyenoch.github.io/solid-gpui/), [registry response](https://registry.npmjs.org/@solid-gpui/core/latest).

## Checks performed during this assessment

- `bun --conditions=browser test packages/solid-gpui/tests/control-flow.test.ts packages/solid-gpui/tests/renderer.test.ts packages/solid-gpui/tests/transport-pressure.test.ts`: **47 passed, 0 failed**.

- First-party npm registry response and live website capture as described above.
- A static comparison of canonical `PROTOCOL_VERSION` against the three host release/candidate scripts reported **five stale v5 assertions** and exited nonzero. This is the reproduced source-consistency failure, not a release-build execution result.
- A controlled-input TestHost probe reproduced the UTF-8/UTF-16 default-selection defect for CJK and an astral character as described above.

No Rust build, native-window acceptance, physical input measurements, remote-project builds, package installation, or cross-project benchmarks were performed. Headless tests establish the tested protocol/reactivity/content contracts, not GPU or operating-system behavior.

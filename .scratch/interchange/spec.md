# Data interchange completeness

## Goal

Audit what data can enter and leave a React GPUI surface, close only bounded
real gaps, and record the platform limits that remain. This pass does not add a
wire surface: the file-I/O workstream owns the shared command/protocol files,
and clipboard images require a new binary value contract.

## Scope and invariants

- This is an audit and documentation pass. No protocol constants, command
  tuples, command-result tags, renderer root interfaces, or image painter code
  change here.
- `ClipboardItem::Image` is encoded image data in a declared format; GPUI does
  not promise an RGBA buffer. A future React surface must preserve this fact.
- `onExternalFileDrop` is a bounded ordered path notification. It does not
  promise a snapshot of filesystem metadata, MIME type, or bytes.
- Clipboard text limits count UTF-8 bytes at resource/protocol boundaries.
  TextInput selection and max-length semantics remain UTF-16 as specified by
  [ADR-0004](../../docs/adr/0004-dual-length-semantics.md).
- Generated images use the existing host path seam. Applications own lifecycle
  and cleanup of temporary files; the image node does not own arbitrary byte
  buffers.

## Future clipboard-image payload draft

This is a design sketch, not a v3 wire change. It is intentionally isolated from
the concurrent file-I/O protocol edits.

1. Add root-only image write/read commands in a future protocol revision. The
   write payload would be a tagged pair such as `[formatCode, bytes]`, where
   `formatCode` is a closed enum for GPUI's supported encoded formats and
   `bytes` is MessagePack `bin`, not a string/base64 value.
2. Add a command-result value tag such as `[6,[formatCode,bytes]]`. The value
   decoder must validate the format, require a non-empty bounded byte vector,
   and reject malformed or over-limit values before dispatch.
3. Set an explicit encoded-byte cap below `MAX_FRAME_LENGTH` so the command and
   result remain framed even after MessagePack/container overhead. The cap must
   be shared by TypeScript and Rust and should be materially smaller than the
   16 MiB frame ceiling; it must not be inferred from the text 1 MiB cap.
4. Return the original encoded format/bytes where the platform can provide
   them. Do not promise RGBA, implicit PNG conversion, or uniform write support:
   macOS and Windows have native read/write paths, X11's current adapter needs
   an image-write cutover, and Wayland's current write path is text-only.
5. Add display-backed tests for each claimed platform path plus bounded
   encode/decode and rejection tests in the headless suite. Do not expose the
   API until the command owner and file-I/O owner agree on command numbering,
   value tags, byte ownership, and failure semantics.

## Verification

- `packages/react-gpui/tests/interchange.test.tsx` locks exact-at-limit and
  one-byte-over-limit writes/reads for three-byte CJK and four-byte emoji.
- Existing package clipboard command coverage remains in
  `packages/react-gpui/tests/renderer.test.tsx:360-430`.
- Pinned macOS GPUI has a direct image clipboard test using a 1×1 PNG
  (`references/zed/crates/gpui_macos/src/pasteboard.rs:500-536`); the repository's
  headless `TestPlatform` stores arbitrary `ClipboardItem` values but has no
  native desktop clipboard (`references/zed/crates/gpui/src/platform/test/platform.rs:27-32,538-544`).
- No CHANGELOG entry is required: this pass changes no runtime behavior.
